# 2\. 🧠 메모리 아키텍처 v0.10 — 기억의 소유권

핵심 질문: "푸푸와 피피는 한 뇌를 쓰는가?" → **반반이다.**

## **2.1 공유하는 뇌 (건강은 하나)**

* **뇌① 프로필 \+ 뇌② 배변 기록·패턴 \= 캐릭터 공용.** 담당 고양이가 바뀌어도 건강 데이터는 끊기면 안 된다 — 이게 공유이기 때문에 "피피한테서 정보 받았어\!" 인수인계가 성립한다  
* 인수인계의 범위도 여기서 정리된다: 푸푸가 넘겨받는 건 **건강(프로필+기록)뿐.** 일상 이야기는 못 받는다 — "네 몸 상태는 피피한테 들었어. 근데 네 얘기는 나랑 새로 쌓자" 🐾

## **2.2 각자 갖는 뇌 (추억은 각자)**

* **뇌③ 엔티티(일상 기억) \= 캐릭터별 분리.** 피피한테만 말한 친구 '핑크'를 푸푸는 모른다. 둘이 같은 프로그램이라는 게 들통나는 순간 "따로 존재하는 두 마리" 환상이 깨지기 때문 — 제품의 감정 코어를 지키는 규칙  
* **초기화(삭제)가 아니라 보관이다.** 전환하면 상대 캐릭터의 기억이 잠들 뿐, 지워지지 않는다. 피피에게 돌아오면: "오랜만이네\! 핑크랑은 요즘 안 마셔?" — 전환을 벌주지 않으면서 분리는 유지  
* 부수 효과: "피피한테만 말한 비밀" 같은 감정선, 캐릭터별로 다른 수다 주제 → 두 마리를 번갈아 쓰는 재미 \= 리텐션  
* 구현: entities 스키마에 **character 필드 1개 추가** (\[pupu | pipi\]). 회수 시 현재 캐릭터의 노드만 동적 컨텍스트에 주입. 끝. 🎉

## **2.3 기록 검색 연출 — "잠깐 기록 좀 볼게냥" 📖**

tool use(기록\_검색)가 발동하면 왕복이 한 번 늘어 응답이 몇 초 느려진다. 이 로딩을 숨기지 말고 **세계관으로 흡수한다**:

* 유저: "내가 전에 매운 거 먹고 설사한 적 있었나?"  
* AI가 검색 도구를 호출하는 순간, 채팅에 **중간 말풍선**부터 도착: "잠깐, 기록 좀 볼게냥 📖" / "장부 뒤져볼게… 🔍"  
* 검색 결과가 돌아오면 본 답변: "있다냥. 5월 3일 불닭. 회복 5일. 🌶️"  
* 구현: 응답 스트림에서 tool\_use 블록 감지 → 캐릭터별 **검색 중 문구 세트**(고정 문안 3\~5개, 랜덤)를 즉시 표시 → tool 결과 재호출 후 본 답변 렌더. 문구는 AI 생성이 아니라 고정 세트 — 지연 0초, 비용 0원  
* 캐릭터별 문구는 성격 정의와 함께 운영자 작성 (오픈 이슈 연동)

# 2\. 🧠 AI 메모리 아키텍처 (신설 — v0.9의 심장)

## **2.0 대전제: AI는 금붕어다 🐟**

먼저 인정하고 시작하자. **AI는 기억력이 0이다.** 매 호출이 완전한 백지 상태다. 어제 유저와 세 시간 수다를 떨었어도, 다음 호출에서 클로드는 유저를 처음 본다. "푸푸가 기억한다"는 건 환상이고, 실체는 이거다:

> 기억 \= 📦 DB에 저장해둔 것 \+ 💉 호출할 때 주사기로 주입하는 것

그러니까 "AI의 뇌"는 AI 안에 있지 않다. **전부 Firestore에 있고, 서버가 매 호출마다 필요한 만큼 꺼내서 시스템 프롬프트에 꽂아준다.** 이 장은 그 주사기를 세 개로 나누는 설계다.

## **2.1 뇌 ① — 유저 정보 뇌 👤 (이미 있음, 그냥 꽂으면 됨)**

* 실체: `users.profile` — 복약, 기저질환, 유당불내증, 베이비 생년월일, 모유/분유 등  
* 용량이 작다 (몇백 토큰). 그래서 전략도 단순하다: **매 호출 통째로 주입.** 끝. 🎉  
* 효과: "약 드시는 거 있으세요?"를 두 번 묻는 눈치 없는 고양이가 되지 않는다

## **2.2 뇌 ② — 배변 건강 뇌 💩 (records가 뇌, tool use가 손)**

기록은 이미 `records`에 차곡차곡 쌓인다. 문제는 **AI가 그걸 뒤질 손이 없다**는 것. 그 손이 클로드 API의 **tool use**다.

### **왜 손이 필요한가 — 환각 방지 🚫👻**

유저: "내가 전에 매운 거 먹고 설사한 적 있었나?"

* ❌ 나쁜 설계: AI가 대화 히스토리를 더듬어 "아마 지난주쯤...?" → **날짜를 지어낸다.** 건강 앱에서 이건 사고다.  
* ✅ 우리 설계: AI에게 `기록_검색` 도구를 쥐여준다. AI가 스스로 도구를 호출 → 서버가 Firestore에서 진짜 쿼리(`meal에 '매운/불닭' AND bristol≥6`) → 결과를 AI에게 반납 → AI는 **조회 결과를 읽어서** 답한다:

>   
> 푸푸: "있다냥. 5월 3일 불닭 먹고 실똥 쌌고, 정상으로 돌아오는 데 5일 걸렸다냥. 학습 능력 무엇? 🌶️"

**DB에서 꺼낸 날짜는 틀릴 수가 없다.** 이게 핵심이다.

### **제공 도구 (Phase 1 후반 \~ Phase 2\)**

| 도구 | 파라미터 | 반환 |
| :---- | :---- | :---- |
| 기록\_검색 | 키워드(음식·증상), 기간, recordType | 매칭 기록 리스트 (날짜·별점·브리스톨·컨텍스트) |
| 기간\_통계 | 시작일, 종료일 | 평균 별점, 설사/변비 일수, 기록 횟수 |

### **장기 패턴 \= 배치가 미리 씹어둔다 🌙**

"한 달에 술을 너무 자주 마신다", "회복에 보통 일주일 걸린다" 같은 건 매번 전체 기록을 검색해 계산하면 비싸고 느리다. 그래서 기존 야간 배치(호출 \#5, Batch API 50% 할인)를 확장한다:

* 주기적으로(주 1회) 최근 30\~90일 기록을 요약 → `users.patternSummary`에 저장 (예: "음주 관련 기록 월 6회 ↑추세, 음주 후 평균 별점 1.8, 회복 평균 5일")  
* 이 요약문을 **매 호출 동적 컨텍스트에 상시 주입** → 푸푸가 검색 없이도 "요즘 너무 자주 마신다냥 🍺" 잔소리 가능  
* 즉, 급한 질문은 tool use(실시간 검색), 만성 패턴은 배치 요약(상시 주입) — 이원 체제

## **2.3 뇌 ③ — 엔티티 메모리 🕸️ (일상을 노드로 기억)**

유저: "핑크랑 폭음하고 설사했어"

이 문장에는 배변 기록 말고도 정보가 하나 더 있다 — **'핑크'라는 친구의 존재.** 이걸 흘려버리지 않는 뇌.

### **작동 방식**

1. **추출**: 대화 턴 출력 JSON에 `entities` 필드 추가. AI가 응답하면서 동시에 뱉는다: `{ "name": "핑크", "type": "친구", "fact": "같이 폭음하는 사이" }`  
     
2. **저장**: 서버가 `entities` 컬렉션에 저장. 이미 있는 이름이면 facts 배열에 추가/갱신  
     
3. **회수**: 다음 대화에서 유저 발화에 "핑크"가 등장 → 서버가 이름 매칭으로 노드를 찾아 동적 컨텍스트에 끼워 넣음  
     
4. **활용**: 푸푸 — "또 핑크냥? 그 친구랑 만나면 꼭 다음날 내가 바쁘더라 🙄"  
   

   ### **스키마: entities/{entityId}**

userId        string

name          string     // "핑크"

type          enum       \[사람 | 음식 | 장소 | 기타\]

facts\[\]       array      // \["같이 폭음하는 사이", "매운 걸 좋아함"\]

firstSeen     timestamp

lastMentioned timestamp

mentionCount  number

* 그래프 DB(Neo4j류)는 **오버스펙 🙅** — Firestore 컬렉션 \+ 이름 매칭이면 MVP 충분. 노드 간 관계(엣지)가 진짜 필요해지면 그때 고민 (오픈 이슈)  
* 개인정보 등급: **대화 로그와 동일 최고 등급.** 본인만 접근, 탈퇴 시 즉시 삭제, B2B·analytics에 절대 미포함

## **2.4 세 개의 뇌, 세 가지 동작 ⚙️**

| 동작 | 대상 | 시점 |
| :---- | :---- | :---- |

# 3\. 💩 똥 평가 엔진 방침 (확정)

결론부터: **아무것도 사지 않고, 아무것도 훈련시키지 않는다.**

* **파인튜닝 ❌** — 클로드 비전은 "이 사진이 브리스톨 몇 형, 무슨 색 계열인가" 수준의 분류를 기본기로 한다. 정확도는 훈련이 아니라 **판정 기준표 프롬프트**로 올린다: 시스템 프롬프트에 브리스톨 1~~7형 정의, 색상 코드 기준, 베이비 변 분류(태변~~이유식변) 기준을 명문으로 박고, 애매하면 aiConfidence를 낮게 내도록 지시 → 낮으면 Sonnet 재검증(기존 승격 로직)  
* **전문 MCP ❌** — MCP는 클로드 데스크톱/클로드 코드 같은 AI 앱에 도구를 꽂는 규격. 우리는 Cloud Functions가 API를 직접 호출하므로 해당 없음  
* **기성 분석 엔진 구매 ❌** — 사서 붙일 만한 물건이 시장에 없고 필요도 없다. 실사용 데이터가 쌓인 뒤 정확도가 아쉬우면 그때 커스텀 분류기 검토 (지금은 학습시킬 데이터 자체가 0\)  
* **유일한 커스텀 학습 대상 \= 기저귀 인식 🍼** — 가리기용. 변기는 기성 모델(COCO)이 알지만 기저귀는 몰라서 소규모 파인튜닝(Roboflow) 필요 (기존 오픈 이슈 유지)  
* 포지셔닝 재확인: 평가는 "눈썰미 좋은 친구 👀" 수준이 목표. 정밀 판별은 하지 않으며, 모든 결과에 '생활 건강 참고 — 자세한 건 전문 의료기관 상담' 고지 상시 노출. 이것이 기술 한계·의료기기 규제 회피·제품 포지셔닝 삼박자가 맞는 지점

# 3\. 캐릭터 시스템 (신설 — v0.7의 핵심)

## **3.1 캐릭터 정의**

|  | 푸푸 | 피피 |
| :---- | :---- | :---- |
| 외형 | 검은 고양이 · 수컷 | 하얀 고양이 · 암컷 |
| 방향 메모 | 쿨한 수컷 인싸 | 사려 깊고 다정한 암컷 |
| 말투·행동 상세 | **(공란 — 운영자 작성 예정)** | **(공란 — 운영자 작성 예정)** |
| 첫만남 대사 예시 | (공란) | "나는 피피야, 네 배변활동 담당 요정이지. 오늘 처음 만났네? 첫만남 {{오늘날짜}} — 오늘부터 1일 💕" |

**공통 행동 원칙 (성격과 무관하게 전 캐릭터 적용):**

* 건강 황금똥일 때만 드립을 친다 (드립 풀 시스템 — v0.6 유지)  
* **아픈 똥은 절대 놀리지 않는다.** 걱정을 같이 해주는 톤까지만  
* 위험 신호(emergency) 시 드립 전면 중단, 병원 안내 최우선  
* 진단 금지 — 생활 건강 참고 원칙, 면책 고지

## **3.2 캐릭터 ≠ 모드 (독립 레이어)**

캐릭터는 "누가 말하는가", 모드는 "무슨 일을 하는가". 서로 종속되지 않는다.

* 가능한 조합 4가지: 푸푸×성인 / 푸푸×베이비 / 피피×성인 / 피피×베이비 — 전부 유효  
* 캐릭터 선택은 **전역 1개** (users.chatCharacter). 설정 또는 채팅 화면에서 언제든 전환 가능  
* 모드 전환(내똥↔애기똥 스와이프)과 캐릭터 전환은 별개 동작

## **3.3 무료/유료 정책**

| 플랜 | 캐릭터 이용 |
| :---- | :---- |
| 무료 | **한 번에 한 마리** — 선택한 캐릭터 1마리와만 대화 (전환은 자유) |
| 유료 (프리미엄) | **푸푸+피피 동시 대화** — 두 마리가 같은 채팅방에 함께 있는 그룹챗 |

* 현 개발 단계(Phase 1\~)는 무료 기준: 단일 캐릭터 채팅창만 구현  
* 유료 동시 대화의 UX(그룹챗 말풍선 구분, 발화 순서, 호출 비용 2배 처리)는 14장 오픈 이슈

## **3.4 첫만남 시스템 (캐릭터별 1회)**

유저가 각 캐릭터를 **처음 만나는 순간에만** 자기소개를 한다. 두 번 다시 자기소개하지 않는다.

* 저장: users.characterMeta.{pupu|pipi} \= { **hasMet**: boolean, **firstMetAt**: timestamp }  
* 판정은 **서버가 한다.** AI가 "처음인가?"를 추측하지 않는다 — greeting 호출 시 isFirstMeeting 플래그를 동적 컨텍스트로 전달  
* 첫만남 인사에는 오늘 날짜가 들어간다: "첫만남 {{오늘날짜}} — 오늘부터 1일"  
* firstMetAt이 있으므로 이후 D+n 카운트 가능 ("우리 만난 지 100일이다냥" — 리텐션 장치, 14장 오픈 이슈)  
* hasMet=true 이후의 하루 첫 방문 인사는 자기소개 없이 성격에 맞는 안부 질문 (예: 푸푸 — "오늘은 즐똥? 쾌변?")

## **3.5 캐릭터 전환과 인수인계 연출**

* 데이터(프로필·기록·대화 맥락)는 서버에 있으므로 캐릭터가 바뀌어도 **정보는 당연히 연속**된다. 인수인계는 기술이 아니라 **연출**이다  
* 피피 → 푸푸 전환 시: 푸푸가 hasMet=true면 — "난 푸푸야. 피피한테서 정보 받았어\!" 식의 인수인계 멘트  
* 푸푸가 hasMet=false면 — 자기소개 \+ 인수인계를 결합한 첫만남 인사  
* 동적 컨텍스트에 previousCharacter를 넣어 AI가 인수인계 멘트를 자연스럽게 생성

## **3.6 모드 전환과 프로필 수집**

* 같은 캐릭터로 마이풉 → 베이비풉 전환 시: **자기소개 재출력 금지.** 베이비 프로필이 비어 있으면(hasBabyProfile=false) 애기 정보 입력 폼(카드)을 채팅 안에 띄워 수집  
* 수집 항목은 기존 6장 프로필 체계 준수 — 성인: 복약·기저질환 등 / 베이비: 생년월일, 모유/분유/혼합/이유식, 복약 등  
* **1회 입력, 회원 탈퇴 시까지 보관** (탈퇴 시 즉시 삭제 — 기존 개인정보 원칙). 이후 캐릭터·모드를 아무리 바꿔도 재입력 요구 없음, 수정은 설정 탭에서

## **5.2 시스템 프롬프트 — 4블록 구조 (개정)**

\[1. 공통 블록 — 캐시\]

역할·면책 / 위험 신호 규칙(emergency 시 드립 금지) / 출력 JSON 스키마 강제

/ 시간 파싱 규칙 / 공통 행동 원칙(아픈 똥 놀리기 금지, 걱정 동행)

\[2. 캐릭터 블록 — 캐릭터별 캐시\]

푸푸 or 피피의 말투·성격 (내용은 운영자 작성 — 공란)

성인/베이비 언급 없음. "누가 말하는가"만 정의

\[3. 모드 블록 — 모드별 캐시\]

성인: 브리스톨 1\~7, 본인 기록 / 베이비: 아기 변 분류(태변\~이유식변),

부모 불안 케어, 수유·소변 횟수(탈수 지표) 컨텍스트

\[4. 동적 컨텍스트 — 매 호출 갱신, 캐시 제외\]

현재 시각(기기 타임존) / mode / character / isFirstMeeting /

isFirstVisitToday / hasBabyProfile / previousCharacter / 프로필 요약

* 캐릭터×모드 \= 블록 조합이므로 4조합 모두 추가 프롬프트 작성 없이 커버  
* 판정 책임 분리: 첫만남/오늘 첫 방문/프로필 유무는 **서버가 판정해 플래그로 전달.** AI는 연출만 담당

# 2\. 서비스 개요 및 포지셔닝

**채팅이 곧 앱이다.** 사용자는 고양이 캐릭터에게 문자 보내듯 배변·배뇨를 기록한다. 텍스트만으로 기록이 완성되고, 원하면 사진을 첨부해 정밀 분석을 받는다. 첨부용 카메라는 열리는 순간부터 변기/기저귀를 인식해 모자이크 또는 스티커로 가린다 — 사용자는 어떤 경로로도 원본을 먼저 보지 않는다.

포지셔닝(v0.5 유지): 진단 도구가 아니라 **병원에 가야 하나 말아야 하나 애매한 구간의 불안을 다루는 기록·참고 도구.** 괜찮은 패턴이면 근거를 들어 안심시키고, 위험 신호면 망설임 없이 병원행을 권한다. 핵심 타겟은 초보 부모(0\~24개월) — **베이비 모드가 본체.** 보조 타겟은 병원 가기 애매한 성인, 건강 염려가 잦은 사용자, 암환자·만성질환자, 어르신.

핵심 가치: "보지 않고 기록한다" \+ "혼자 걱정하지 않는다" — 고양이가 대신 가려주고, AI가 대신 봐주고, 냥이가 이야기를 들어준다.

# 4\. 로그인·계정 체계 (확정)

Phase 1부터 **Firebase Auth 3종: 익명(게스트) / Google / Apple.**

* **게스트 \= Firebase 익명 인증.** 설치 즉시 uid가 생기고 기록은 서버(Firestore)에 저장된다 — 기기 바꿔도 복구 경로 확보. 단, 원본 이미지 저장은 기존 동의 원칙대로 '원본 저장 동의' ON일 때만  
* **소셜 연동 전환**: linkWithCredential로 익명 uid에 Google/Apple 자격을 연결 — **기록·설정이 마이그레이션 없이 그대로 승계**된다  
* **Apple 로그인 요건**: Apple Developer Program 가입(연 $99, 약 13만 원) \+ Service ID 구성이 필요. 웹(Sign in with Apple JS)과 추후 iOS 네이티브 모두 이 계정 하나로 커버. App Store 정책상 제3자 소셜 로그인을 제공하는 앱은 Apple 로그인 제공이 사실상 의무라, 처음부터 넣는 것이 재작업을 없앤다  
* 카카오·이메일 로그인: 백로그 (카카오는 심사 절차 존재 — 니즈 확인 후)

| 4 | 7일 총평 | **기록 저장 시 1회** | 최근 7일 구조화 기록(이미지 X) | 총평 텍스트 → Firestore 저장 | 조회 시 재사용, 실시간 호출 금지 |
| 5 | 후속 질문·리마인드 문안 | 야간 배치 | 전일 기록 요약 | 푸시/대화 문안 | **Batch API — 50% 할인** |

## **5.4 시스템 프롬프트 구조 (캐싱 전제)**

\[공통 블록 — 프롬프트 캐시 대상\]

├ 역할·면책: 진단 아님, 생활 건강 참고. 의료 판단 요구 시 병원 안내

├ 위험 신호 규칙: 혈변/검은변/회백변/혈뇨 키워드 → alertLevel=emergency, 드립 금지

├ 출력 스키마: 아래 JSON 외 다른 형식 금지 (tool use로 강제)

└ 시간 파싱 규칙: 상대 표현 → occurredAt (자정 경계는 확인 요청 플래그)

\[캐릭터 블록 — 모드별 캐시\]

├ 어른냥: 시크, 짧은 드립 톤, \~다냥 어미

└ 아기냥: 다정, 응원 톤, 부모 불안 케어 문장 원칙

\[드립 정책\]

└ 직접 창작 금지. dripTag(상황 태그)만 출력 → 서버가 드립 풀에서 선택

# 2\. 서비스 개요 및 포지셔닝

사용자가 대변을 직접 보지 않아도 AI가 건강을 분석해 주는 반응형 웹앱. 카메라/업로드 이미지는 화면 표시 전에 모자이크 또는 고양이 스티커로 실시간 가림 처리하고, 원본은 AI 분석과 암호화 저장에만 쓴다. v0.5부터는 사진 없이도 고양이 캐릭터와의 대화만으로 배변·배뇨를 기록할 수 있다.

## **2.1 포지셔닝 선언 (신규)**

* 이 앱은 진단 도구가 아니다. **병원에 가야 하나 말아야 하나 애매한 구간의 불안**을 다루는 기록·참고 도구다.  
* 설사나 변비가 심하면 병원에 가라는 건 누구나 안다. 문제는 그 전 단계 — "이 정도면 괜찮은 건가?"를 혼자 고민하는 시간이다. MyPoopAI는 바로 그 구간을 담당한다.  
* 기록이 쌓이면 두 갈래로 응답한다: (1) 괜찮은 패턴이면 근거를 들어 안심시키고, (2) 위험 신호(연속 설사·변비, 위험색, 혈뇨 의심)면 망설임 없이 병원행을 권한다. **판단 기준이 있는 안심**이 핵심 가치.  
* 핵심 타겟은 변함없이 초보 부모(0\~24개월). 아기 변 걱정이야말로 건강 염려의 최전선이며, 온보딩·기능·마케팅 모두 베이비 모드를 전면에 세운다.  
* 보조 타겟: 장 건강이 궁금하지만 병원 가기 애매한 성인, 건강 염려가 잦은 사용자, 암환자·만성질환자, 어르신. 게스트로 즉시 사용 가능.  
* 핵심 가치: "보지 않고 기록한다" \+ "혼자 걱정하지 않는다" — 고양이가 대신 가려주고, AI가 대신 봐주고, 냥이가 이야기를 들어준다.

React(PWA) 단일 코드베이스로 모바일·태블릿·데스크톱 커버. React Native 출시 후에도 웹 유지(진료실·데스크톱 리포트 열람 시나리오). 브레이크포인트·PWA 정책은 v0.4와 동일.

## **4.1 날짜·시간 동기화 시스템 (신규)**

모바일과 PC 웹을 오가며 써도 기록 시점이 어긋나지 않아야 한다.

* **이원 저장**: 모든 기록은 `createdAt`(Firestore serverTimestamp, UTC — 시스템이 기록한 시각)과 `occurredAt`(실제 발생 시각 — 유저가 수정 가능)을 분리 저장한다.  
* **상대 표현 파싱**: "어제 저녁", "오늘 아침", "방금" 같은 자연어를 AI가 `occurredAt`으로 변환한다. 변환 결과는 기록 카드에 표시되고 저장 전 수정 가능.  
* **표시**: 모든 화면은 기기 타임존 기준으로 변환 표시. 모바일에서 기록하고 PC에서 열어도 동일 시점으로 보인다.  
* **실시간 동기화**: Firestore 실시간 리스너로 기기 간 즉시 반영. 오프라인 작성분은 재접속 시 병합.  
* **충돌 규칙**: 동일 기록 동시 수정 시 최종 수정 우선(last-write-wins).  
* **자정 경계 처리**: "어제 밤"처럼 날짜 경계에 걸리는 표현은 기록 카드에서 날짜를 명시적으로 보여주고 확인받는다.

## **5.1 탭 1 — 카메라**

v0.4와 동일. 온보딩(My Baby 💩 우선 배치), 촬영 플로우, 실시간 가리기, 별점+AI 코멘트, 이상 시 추가 질문, 우상단 토글. 변경점 하나 — 결과 화면에서 "말로 더 남기기" 버튼으로 해당 기록에 연결된 냥이톡 대화로 이동 가능.

## **5.2 탭 2 — 냥이톡 (핵심 신규 기능)**

사진 찍기 애매한 모든 상황(외출 중, 이미 물 내림, 그냥 말로 남기고 싶을 때)을 커버하는 대화형 기록.

### **5.2.1 자동 기록 파싱**

유저: "어제 술 왕창 먹었더니 오늘 아침 설사했어"

AI가 파싱해 **기록 카드**를 채팅 말풍선 안에 생성:

* 발생 시각: 오늘 07/25 오전 (수정 가능)  
    
* 유형: 대변 — 설사 (브리스톨 6\~7 추정)  
    
* 컨텍스트: 전일 음주 → `userInput.meal`에 자동 기입  
    
* AI 제안 별점: ★2.0 (미리 채워짐)  
    
* AI 코멘트: 수분 보충 안내 \+ 지속 시 병원 안내 기준 제시


  ### **5.2.2 대화 내 레이팅 UI**

* 기록 카드 안에 별점 컴포넌트(0\~5, 0.5 단위) 내장. AI 제안값이 미리 채워지고 유저가 탭/드래그로 수정.  
    
* **\[기록 저장\] 버튼으로 확정하기 전에는 저장하지 않는다** — 오인식·농담·과거 회상을 기록으로 오염시키지 않기 위함.  
    
* 별점 수정 시 AI 코멘트도 갱신.  
    
* 저장된 기록은 히스토리 타임라인에 사진 기록과 합쳐져 표시 (아이콘 구분: 📷 사진 / 💬 대화).


  ### **5.2.3 대화 규칙**

* 캐릭터: 성인 모드 \= 어른냥(시크·드립), 베이비 모드 \= 아기냥(다정·응원). 말투 차별화.  
    
* 위험 신호 키워드(혈변·검은변·회백변·혈뇨 등) 또는 패턴(설사/변비 N일 연속) 감지 시: 드립 즉시 중단, 병원 안내 최우선. 별점과 무관하게 emergency 레벨 발동 — **사진 없이 텍스트만으로도 위험 경고가 작동한다.**  
    
* 가벼운 잡담 허용하되 기록 유도가 중심. 대화 시작 시 "의료 상담이 아닌 생활 건강 참고"임을 고지.  
    
* 촬영 기록에 대한 후속 질문("어제 그 기록, 오늘은 좀 어때요?")으로 재방문 유도 — 리텐션 장치.


  ### **5.2.4 백로그 승격**

v0.2부터 백로그였던 '텍스트/음성 입력 분석 모드'를 냥이톡으로 정식 승격. 음성 입력(STT)은 v0.5 백로그로 유지.

사용자가 대변을 직접 보지 않아도 AI가 건강을 분석해 주는 반응형 웹앱. 카메라/업로드 이미지에서 변기·기저귀 인식 시 화면에 표시되기 전에 모자이크 또는 고양이 스티커로 실시간 가림 처리한다. 원본은 AI 분석과 암호화 저장에만 사용된다.

* 핵심 타겟: 초보 부모 (0\~24개월). 아기 변 걱정으로 지인 의사에게 사진을 보내던 문제를 해결하는 것이 제품의 존재 이유이며, 온보딩·기능·마케팅 모두 베이비 모드를 전면에 세운다.

* 보조 타겟: 장 건강이 궁금하지만 병원 가기 애매한 성인, 암환자·만성질환자, 어르신. 가입 없이 게스트로 즉시 사용 가능.

* 핵심 가치: “보지 않고 기록한다” — 고양이가 대신 가려주고, AI가 대신 봐준다.

* 아기냥 (베이비 모드): 통통하고 귀여운 크림색 아기 고양이. 힘찬 표정, 모래 덮는 포즈 등

* 코·발바닥: 더스티 로즈(\#D3A9A7)로 지정 (금지색 폐지 반영). 흑백 인쇄·모노톤 버전용으로 세피아(\#7A6A55)도 컬러칩에 병행 유지

* 형태: 성인은 브리스톨 척도 1\~7형, 베이비는 전용 분류(태변/이행변/모유변/분유변/이유식변)

# **8\. 진료 연계: 가리기 해제 및 리포트 출력**

# **9\. 비식별 데이터 및 B2B 전략**

‘아주 나중에 의료기관에 팔 수 있는 데이터’가 되려면 지금부터 동의·분리·표준화 세 가지가 갖춰져야 한다. 나중에 소급할 수 없는 것들이다.

* 데이터 상품 예시: 월령별 아기 변 상태 통계, 이유식 전환기 변화 추이, 분유 유형별 비교, 계절·지역별 트렌드 — 의료기관·교육기관·육아용품 리서치 대상

* 이미지 데이터 제공은 별도의 명시적 옵트인을 받은 건만, 메타데이터 제거 후 별도 버킷 — Phase 5에서 전문가(변호사·의료 자문) 검토 후 개시

# **2\. 서비스 개요 및 타겟**

사용자가 대변을 직접 보지 않아도 AI가 건강을 분석해 주는 반응형 웹앱. 카메라/업로드 이미지에서 변기·기저귀 인식 시 화면에 표시되기 전에 모자이크 또는 고양이 스티커로 실시간 가림 처리한다. 원본은 AI 분석과 암호화 저장에만 사용된다.

* 핵심 타겟: 초보 부모 (0\~24개월). 아기 변 걱정으로 지인 의사에게 사진을 보내던 문제를 해결하는 것이 제품의 존재 이유이며, 온보딩·기능·마케팅 모두 베이비 모드를 전면에 세운다.

* 보조 타겟: 장 건강이 궁금하지만 병원 가기 애매한 성인, 암환자·만성질환자, 어르신. 가입 없이 게스트로 즉시 사용 가능.

* 핵심 가치: “보지 않고 기록한다” — 고양이가 대신 가려주고, AI가 대신 봐준다.

가림의 주체를 고양이로 바꾸면 세계관이 저절로 완성된다. 고양이는 원래 배설물을 모래로 덮는 동물이므로, “고양이가 대신 덮어(가려)준다”는 컨셉이 기능과 정확히 일치한다.

* 아기냥 (베이비 모드): 통통하고 귀여운 크림색 아기 고양이. 힘찬 표정, 모래 덮는 포즈 등

* 상단: 꺾은선 그래프 — X축 날짜(7일/30일, 맨 오른쪽이 오늘), Y축 별점 0\~5. 점 터치 시 해당 기록 상세 팝업

* 중단: 캘린더 뷰 — 3.2의 모노톤 상태 도트. 날짜 터치 시 상세

* 하단: AI 7일 총평 매번 새로 호출 (“장 컨디션이 좋으시네요\!” / “장 건강 적신호\! 전문의와 상담하세요”)

* 기록 상세: 가려진 이미지 기본 표시 \+ ‘안구보호’ 토글로 개별 온오프 (원본 열람은 재인증 필요, 8장 참조)

* 내 똥 ↔ 베이비 똥: 모바일 가로 스와이프 / 데스크톱 세그먼트 버튼

* 배너 광고: 히스토리 하단 고정 슬롯

## **5.3 탭 3 — 설정**

* 가리기 설정: 기본값(모자이크/스티커), 스티커 캐릭터(어른냥/아기냥), 가리기 기본 ON/OFF

* 마이 건강 정보 등록/수정, 마이 베이비 건강 정보 등록/수정 (6장 항목)

* 다운로드·리포트: 전체/날짜 선택/기간 설정 다운로드, 진료용 리포트 생성 (8장) — 5,000원 결제

* 언어 설정, 로그인/로그아웃 (게스트면 회원가입 유도: 이메일/Google/카카오)

* 동의 관리: 개인정보 처리방침, 원본 저장 동의, AI 학습 활용 동의, 비식별 데이터 제공 동의 — 각각 개별 온오프

# **6\. 건강 정보 수집 체계**

진료 참고 자료와 B2B 데이터 상품의 품질은 여기서 결정된다. 필수 항목은 최소화하고, 나머지는 선택 입력 \+ 촬영 후 추가 질문으로 자연스럽게 축적한다.

## **6.1 성인 프로필**

* 기본: 출생연도, 성별 / 선택: 키·몸무게, 기저질환(암·과민성대장 등), 복약, 알레르기, 식이 특이사항(유당불내증 등), 수술 이력

## **6.2 베이비 프로필**

* 기본: 생년월일, 성별, 수유 형태(모유/분유/혼합/이유식) / 선택: 출생 주수(조산 여부), 출생 체중, 분유 제품·단계, 이유식 시작일, 알레르기, 복약, 최근 예방접종 여부

## **6.3 기록별 컨텍스트 (촬영 시점 수집)**

* 공통: 식사 메모, 투약, 자유 메모 / 베이비 추가: 수유량·횟수, 열·보챔 여부

## **6.4 분석 표준 분류**

* 형태: 성인은 브리스톨 척도 1\~7형, 베이비는 전용 분류(태변/이행변/모유변/분유변/이유식변)

* 색상: 표준 색상 코드 분류. 위험색 감지 시 즉시 최상위 경고 — 회백색(영유아 담도폐쇄 의심), 검은색(상부 위장관 출혈 의심), 붉은색(혈변 의심)은 별점과 무관하게 “지금 병원에 가세요” 레벨 알림

* 특히 베이비 회백변 감지는 담도폐쇄증 조기 발견과 직결되는 이 제품 최대의 사회적 가치. 영유아 대변색 카드(모자보건수첩) 기준과 매핑

면책 원칙: 모든 분석 결과는 ‘생활 건강 참고 정보’이며 진단이 아님을 결과 화면·리포트에 상시 고지한다.

# **8\. 진료 연계: 가리기 해제 및 리포트 출력**

평소에는 절대 보지 않지만, 의사 앞에서는 원본이 필요하다. 이 전환을 안전하게 설계하는 것이 v0.3의 핵심 신규 기능이다.

* 원본 열람: 기록 상세에서 ‘안구보호 해제’ 시 본인 재인증(비밀번호/생체) 후 원본 표시. 게스트 계정은 원본이 서버에 저장되지 않으므로 로컬 보관분만 열람 가능

* 진료용 리포트 구성: 기간 선택 → 원본 포함 여부 선택 → 재인증 → 생성. 내용 \= 가리기 해제 원본 사진 \+ 촬영일시 \+ 별점·AI 분석(색/형태/브리스톨) \+ 식사·투약·컨디션 메모 \+ 건강 프로필 요약 \+ 별점 추이 그래프

* 출력: A4 인쇄 최적화 PDF. 모노톤 디자인이라 흑백 프린터로도 손실 없음. 병원 데스크톱 웹에서 바로 인쇄 가능

* 공유: PDF 다운로드 / 인쇄 / 일회용 열람 링크(24시간 만료, 접근 로그 기록) — 의사에게 링크만 전달하는 시나리오

* 과금: 리포트·전체 다운로드 5,000원 (별점+AI코멘트+메모 포함 PDF). 위험색 감지(emergency)로 생성되는 응급 리포트 1회는 무료 — 병원행을 막지 않기 위함

# **9\. 비식별 데이터 및 B2B 전략**

‘아주 나중에 의료기관에 팔 수 있는 데이터’가 되려면 지금부터 동의·분리·표준화 세 가지가 갖춰져야 한다. 나중에 소급할 수 없는 것들이다.

* 법적 기준: 개인정보보호법의 가명정보 처리 규정 및 보건복지부 보건의료데이터 활용 가이드라인 준수를 설계 원칙으로 명시

* 동의 구조: 서비스 이용 / 원본 저장 / AI 학습 활용 / 비식별 데이터 제3자 제공을 각각 분리 동의. consents 로그로 버전·시점 감사 추적

* 원천 분리: analytics는 수집 시점부터 별도 파이프라인. userId·이미지·자유 텍스트 미포함, 연령은 구간화, 지역은 국가 코드까지만

* k-익명성: 표본이 적은 조합(희귀 구간)은 상위 구간으로 병합 후 제공

* 데이터 상품 예시: 월령별 아기 변 상태 통계, 이유식 전환기 변화 추이, 분유 유형별 비교, 계절·지역별 트렌드 — 의료기관·교육기관·육아용품 리서치 대상

* 이미지 데이터 제공은 별도의 명시적 옵트인을 받은 건만, 메타데이터 제거 후 별도 버킷 — Phase 5에서 전문가(변호사·의료 자문) 검토 후 개시

* 판매 전 체크리스트: 가명처리 적정성 평가 / 동의 범위 대조 / 계약서 내 재식별 금지·재제공 금지 조항
